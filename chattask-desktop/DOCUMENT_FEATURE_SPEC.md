# ドキュメント機能 仕様書

## 1. 目的

ChatTaskのドキュメント機能は、タスクまたは案件タグに関連する手順書、調査記録、チェックリスト、コード、表などをMarkdownで作成・整理するための機能です。

別ツールへ移植する際は、次の3要素を独立した機能として扱います。

1. 文書・フォルダを管理するドキュメントツリー
2. Markdownを直接編集するテキストエディタ
3. Markdownを安全にHTML表示するプレビュー

## 2. ドキュメントの適用範囲

ドキュメントには2種類の保存先があります。

| 種類 | 用途 | 保存単位 |
| --- | --- | --- |
| タスクドキュメント | 特定タスクだけで使用する手順や記録 | `Task.documents` |
| 案件共通ドキュメント | 同じ案件タグを持つ複数タスクから参照する資料 | `ProjectTag.sharedDocuments` |

タスクに案件タグが設定されている場合、ドキュメント画面から「案件共通ドキュメント」と「タスクのドキュメント」を相互に切り替えられます。

## 3. データモデル

### 3.1 文書・フォルダ

```ts
interface TaskDocument {
  id: string;
  title: string;
  content: string;
  kind?: "document" | "folder";
  parentId?: string;
  createdAt: string;
  updatedAt: string;
}
```

| フィールド | 必須 | 説明 |
| --- | --- | --- |
| `id` | 必須 | 文書またはフォルダを識別する一意ID |
| `title` | 必須 | 画面表示名。Markdown出力時のファイル名にも利用 |
| `content` | 必須 | Markdown本文。フォルダの場合は空文字 |
| `kind` | 任意 | `document` または `folder`。未設定の旧データは `document` として扱う |
| `parentId` | 任意 | 親フォルダのID。空文字または未設定は最上位 |
| `createdAt` | 必須 | ISO 8601形式の作成日時 |
| `updatedAt` | 必須 | ISO 8601形式の最終更新日時 |

### 3.2 ツリー構造

- フォルダと文書は同じ配列に保存します。
- 親子関係は `parentId` で表現します。
- フォルダは文書と別テーブルに分離しません。
- フォルダの配下には、文書と別のフォルダの両方を配置できます。
- フォルダを自分自身または自分の子孫へ移動する操作は禁止します。
- フォルダを削除すると、配下の文書とフォルダもまとめて削除します。

### 3.3 表示設定

次の設定は文書本文とは分離し、文書IDごとのユーザー設定として保存します。

```text
chatTaskMarkdownViewMode:{documentId}
chatTaskMarkdownScrollSync:{documentId}
```

| 設定 | 値 | 初期値 |
| --- | --- | --- |
| 表示モード | `edit` / `split` / `preview` | `split` |
| スクロール同期 | `true` / `false` | `true` |

別ツールでは、ローカル設定、ユーザー設定テーブル、ブラウザストレージなどへ保存できます。本文データには含めない設計を推奨します。

## 4. 画面構成

ドキュメント画面は大きなモーダルまたは専用ページとして表示します。

```text
┌──────────────────────────────────────────────────────────┐
│ タスク名 — ドキュメント                              閉じる │
├──────────────┬───────────────────────────────────────────┤
│ 関連資料切替   │ 文書タイトル                              │
│ 文書／フォルダ │ Markdownツールバー・表示切替               │
│ MDインポート   ├──────────────────┬────────────────────────┤
│               │ テキスト編集部      │ プレビュー部             │
│ ツリー         │                  │                        │
│               │                  │                        │
├──────────────┴──────────────────┴────────────────────────┤
│ 削除確認                         保存状態／MD出力／今すぐ保存 │
└──────────────────────────────────────────────────────────┘
```

### 4.1 左サイドバー

- 関連するタスク資料または案件共通資料への切り替え
- 新規文書の作成
- 新規フォルダの作成
- Markdownファイルのインポート
- 文書・フォルダの階層ツリー
- ドラッグ＆ドロップによるフォルダ移動
- 「最上位へ移動」ドロップ領域

### 4.2 メイン領域

- 文書またはフォルダのタイトル編集
- 文書選択時はMarkdownエディタを表示
- フォルダ選択時はフォルダ案内を表示
- 保存状態、削除、Markdown出力、即時保存を表示

## 5. 文書とフォルダの操作仕様

### 5.1 新規文書

1. 「文書」を押します。
2. `新しいドキュメント` というタイトルで作成します。
3. 現在選択中の場所がフォルダなら、そのフォルダ内に作成します。
4. 文書を自動選択し、編集可能な状態にします。

### 5.2 新規フォルダ

1. 「フォルダ」を押します。
2. `新しいフォルダ` というタイトルで作成します。
3. 現在選択中の場所がフォルダなら、そのフォルダ内に作成します。
4. フォルダを自動選択します。

### 5.3 名前変更

- メイン領域上部のタイトル入力欄で変更します。
- 変更時に `updatedAt` を現在日時へ更新します。
- ツリーの表示名にも即時反映します。

### 5.4 移動

- ツリー上の文書またはフォルダをドラッグします。
- 移動先フォルダへドロップすると `parentId` を変更します。
- 「最上位へ移動」へドロップすると `parentId` を空文字にします。
- 循環参照になる移動は拒否し、エラーメッセージを表示します。

### 5.5 削除

- 文書削除は確認操作を必要とします。
- フォルダ削除時は「配下の文書も含めて削除する」ことを明示します。
- 削除後は、同じ親フォルダ内の別項目、または先頭項目を選択します。
- 削除は待機中の自動保存を待たず、即時保存します。

## 6. Markdownエディタ仕様

### 6.1 基本方針

- 編集部は `contentEditable` や独自ブロックDOMではなく、標準の `textarea` を使用します。
- 保存値はMarkdownのプレーンテキストです。
- Reactなどの画面状態を本文データへ混在させません。
- 日本語IME変換中は、Enter、Tab、Markdown補助処理を実行しません。
- ブラウザまたはOS標準の選択、コピー、貼り付け、Undo、Redoを利用できます。

### 6.2 表示モード

文書ごとに次の3モードを選択できます。

| モード | 表示内容 |
| --- | --- |
| テキストのみ | Markdown編集部のみ |
| プレビューのみ | レンダリング結果のみ |
| 両方 | 左に編集部、右にプレビュー |

初期表示は「両方」です。狭い画面では上下2段表示に切り替えます。

### 6.3 ツールバー

| ボタン | 挿入・変換内容 |
| --- | --- |
| テキスト | カーソル位置へ改行を追加 |
| 見出し | 対象行の先頭へ `## ` を追加 |
| 箇条書き | 対象行の先頭へ `- ` を追加 |
| 番号 | 対象行の先頭へ `1. ` を追加 |
| チェック | 対象行の先頭へ `- [ ] ` を追加 |
| 表 | 3列のMarkdown表テンプレートを挿入 |
| コード | 選択範囲をコードフェンスで囲む |
| 太字 | 選択範囲を `**` で囲む |
| イタリック | 選択範囲を `*` で囲む |
| 下線 | 選択範囲を `<u>` と `</u>` で囲む |

文字列を選択していない場合は、編集対象となるプレースホルダー文字列を挿入・選択します。

### 6.4 Tabと字下げ

- `Tab` はタブ文字ではなく半角スペース4文字を挿入します。
- 複数行を選択して `Tab` を押すと、各行へ半角スペース4文字を追加します。
- `Shift + Tab` は、各行の先頭から最大4文字の半角スペースを削除します。
- Markdownの入れ子リストとしてプレビューへ反映されます。

### 6.5 Enterとリスト継続

通常のEnterでは、現在行の字下げを次の行へ引き継ぎます。

リスト行では、次のマーカーも自動挿入します。

| 現在行 | 次の行 |
| --- | --- |
| `- 項目` | `- ` |
| `* 項目` | `* ` |
| `+ 項目` | `+ ` |
| `1. 項目` | `2. ` |
| `- [ ] 項目` | `- [ ] ` |
| `- [x] 項目` | `- [ ] ` |

空のリスト行でEnterを押した場合は、リストを終了して通常行へ戻します。空の字下げ行でEnterを押した場合も字下げを解除します。

IME変換確定のEnterと改行処理が同時に実行されないよう、`isComposing` とキーコード `229` を確認します。

## 7. Markdown表示仕様

### 7.1 パーサー

- CommonMarkを基本とします。
- GitHub Flavored Markdown（GFM）を有効にします。
- 単一改行を改行として表示します。
- Markdown表、チェックリスト、コードフェンス、リンクなどを表示します。

現行実装では `marked` を次の設定で使用しています。

```ts
marked.parse(text, {
  async: false,
  breaks: true,
  gfm: true,
});
```

### 7.2 セキュリティ

- Markdownから生成したHTMLは必ずサニタイズします。
- 現行実装では `DOMPurify.sanitize` を使用しています。
- リンクは新しいタブまたは外部ブラウザで開きます。
- リンクには `rel="noopener noreferrer"` を付与します。
- 未検証HTMLをそのまま `innerHTML` へ渡してはいけません。

### 7.3 表示対象

- 見出し
- 段落、改行
- 箇条書き、番号リスト、入れ子リスト
- チェックリスト
- 太字、イタリック
- 下線用HTML
- リンク
- 引用
- 水平線
- インラインコード、コードフェンス
- Markdown表

### 7.4 水平線の補正

コードフェンス外にあるハイフン3文字以上の行は、前後へ空行を補って水平線として解釈します。コードフェンス内のハイフンは変更しません。

## 8. スクロール仕様

### 8.1 編集・プレビュー同期

- 「両方」表示時だけ同期できます。
- 初期値は同期ONです。
- 編集部とプレビュー部のスクロール可能量に対する比率で同期します。
- ユーザーが現在操作している側を同期元として扱います。
- 反対側で発生したプログラム由来のスクロールを再同期しないようにします。
- 操作終了から180ミリ秒後に同期元を解除します。

この方式は段落単位の厳密同期ではなく、文書全体に対するスクロール比率同期です。

### 8.2 全画面プレビュー

- プレビュー部の「全画面」で開きます。
- `Esc` で閉じます。
- `Command/Ctrl + Shift + P` で開閉できます。
- 通常プレビューと全画面プレビューのスクロール比率を引き継ぎます。

## 9. 保存仕様

### 9.1 自動保存

- 文書配列が変更されると保存待ち状態へ移ります。
- 最後の変更から1.2秒後に保存します。
- 連続入力中はタイマーを更新し、不要な保存回数を抑えます。
- 画面を閉じる際に未保存データがあれば即時保存します。
- `Command/Ctrl + S` で即時保存できます。
- 「今すぐ保存」でも即時保存できます。

### 9.2 保存状態

画面には次の状態を表示します。

| 内部状態 | 表示 |
| --- | --- |
| `saved` | 保存済み |
| `unsaved` | まもなく保存 |
| `saving` | 保存中… |
| `error` | 保存できませんでした |

### 9.3 保存APIの契約

UIコンポーネントは保存先へ直接依存せず、次のコールバックを呼びます。

```ts
onSave(documents: TaskDocument[]): void
```

別ツールでは、このコールバック部分をSQLite、REST API、IndexedDBなどへ差し替えます。サーバー保存を非同期化する場合は `Promise` を返し、成功後に `saved`、失敗時に `error` へ遷移させる設計へ変更してください。

## 10. Markdownインポート

- `.md` と `.markdown` を受け付けます。
- ファイル選択とドラッグ＆ドロップの両方に対応します。
- 複数ファイルを一括インポートできます。
- ファイル名から拡張子を除いた文字列を文書タイトルにします。
- ファイル本文をそのまま `content` へ保存します。
- 選択中のフォルダがある場合、その配下へ追加します。
- 対象外ファイルしかない場合はエラーを表示します。

## 11. Markdown出力

- 選択中の文書を1つの `.md` ファイルとして出力します。
- 文書タイトルを基本ファイル名として使用します。
- フォルダは出力できません。
- 出力前に未保存変更を保存します。
- 現行デスクトップ版はTauriコマンド `export_markdown` を呼びます。

```ts
exportMarkdown(fileName, content)
```

Web版へ移植する場合は、Blobとダウンロードリンクを使う実装へ差し替えられます。

## 12. エラー・保護仕様

- 不正な親子移動を拒否します。
- 削除前に確認を求めます。
- フォルダ削除時は配下も削除されることを表示します。
- 保存失敗を画面へ表示します。
- インポート対象外ファイルを拒否します。
- Markdown出力失敗を画面へ表示します。
- Markdown由来HTMLをサニタイズします。
- 外部リンクは元画面と分離して安全に開きます。

## 13. 現行仕様の制約

- 文書の並び順を明示する `sortOrder` はありません。配列順で表示します。
- 文書検索、全文検索、タグ付け、変更履歴、共同編集はありません。
- 文書単位のアクセス権限はありません。
- フォルダ単位のMarkdown一括出力はありません。
- 競合解決や楽観ロックはありません。
- スクロール同期は行や見出しではなく全体比率です。
- 表はMarkdownソースを編集する方式で、スプレッドシート型のセル編集ではありません。
- 画像アップロードをMarkdown本文へ挿入する専用機能はありません。

## 15. SQLiteへ移植する場合のテーブル例

```sql
CREATE TABLE documents (
  id TEXT PRIMARY KEY,
  scope_type TEXT NOT NULL CHECK (scope_type IN ('task', 'project_tag')),
  scope_id TEXT NOT NULL,
  parent_id TEXT,
  kind TEXT NOT NULL CHECK (kind IN ('document', 'folder')),
  title TEXT NOT NULL,
  content TEXT NOT NULL DEFAULT '',
  sort_order INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  FOREIGN KEY (parent_id) REFERENCES documents(id) ON DELETE CASCADE
);

CREATE INDEX idx_documents_scope
  ON documents(scope_type, scope_id, parent_id, sort_order);
```

移植先で外部キーを有効にし、フォルダ削除時の子孫削除を `ON DELETE CASCADE` で保証すると、アプリ側だけで整合性を管理する必要が減ります。

表示設定を同期する場合は、別テーブルへ分離します。

```sql
CREATE TABLE document_preferences (
  document_id TEXT NOT NULL,
  user_id TEXT NOT NULL,
  view_mode TEXT NOT NULL DEFAULT 'split',
  scroll_sync INTEGER NOT NULL DEFAULT 1,
  PRIMARY KEY (document_id, user_id)
);
```

## 16. 最低限の受け入れ条件

### 文書管理

- 文書とフォルダを作成できる
- フォルダを多段階に入れ子にできる
- ドラッグで別フォルダまたは最上位へ移動できる
- 循環参照を作成できない
- フォルダ削除時に配下も削除される

### 編集

- 日本語IMEで文字が消えたり、確定時に余分な改行が入ったりしない
- 通常のテキスト選択、コピー、貼り付け、Undo、Redoができる
- TabとShift+TabでMarkdownの字下げを操作できる
- Enterでリストと字下げを継続できる
- 空行でEnterを押すとリストまたは字下げを終了できる

### 表示

- テキストのみ、プレビューのみ、両方を切り替えられる
- 文書ごとに表示モードを保持する
- Markdown表、リスト、コード、リンクを表示できる
- 編集部とプレビューのスクロールを同期できる
- 全画面プレビューを開閉できる
- 危険なHTMLやスクリプトを表示しない

### 保存・入出力

- 連続入力時に過剰な保存を行わない
- 画面を閉じる前に未保存内容を保存する
- 保存状態を確認できる
- Markdownを複数ファイルからインポートできる
- 選択文書をMarkdownファイルとして出力できる
