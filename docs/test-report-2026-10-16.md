### 発見した問題と再現手順

#### CU-01：正常操作で保存した作業別実績を整合性診断が不正日付と判定する

優先度：中。Desktopで再現。実績の保存・今日の集計・再起動・バックアップ復元は成功しているが、診断が不要な修正を促す。

1. 単日予定のあるTaskを用意する。今回の対象はAの作業A2。
2. 今日で作業を開始し、タイマーを終了する。
3. 実績0.25h、作業記録、達成を保存する。
4. 今日の実績0.25h・対応済み1件を確認する。
5. 設定→データ管理→データ管理・バックアップ→診断を実行。
6. `2026-10-16::cc8a1ced-2722-475e-a79c-46cea0d69198` に対し、「要修正 日別実績」「日付または日別実績工数が不正です。」と表示される。

期待：アプリ自身の保存形式による有効な作業別実績を受け入れる。実際：正しい日付と0以上の工数へ修正するよう表示する。証跡：[診断画面](test-evidence-2026-10-16/06-integrity-after-timer.png)。

コード確認による補足（画面操作結果とは別）：`src/services/integrityCheck.ts:89` はdailyActualHoursのキー全体を日付検証する。一方、`src/components/TodayModal.tsx:300` は `date::rangeId` を有効な集計対象として扱うため、診断側の形式不一致による誤検出と判断した。修正は行っていない。

#### CU-02：通常のJSONエクスポート／インポートで今日の作業グループが引き継がれない

優先度：中。Webから別保存領域のDesktopへの移行で確認。

1. Webの今日で、G3（C1→A1）とB1をCU-AI統合グループにする。
2. 通常のデータエクスポートでJSONを書き出す。
3. 別識別子の空のDesktopテスト環境へ読み込む。
4. タスクと予定は読み込まれるが、今日のAI相談ではグループ単位ではなく個別作業が対象として表示される。

実ファイル `test-tasks-export.json` のtodayTaskOrdersには作業IDの平坦な順番だけがあり、グループ名・グループ所属の保存値は含まれない。コード確認では、`src/components/todayExecutionGroups.ts:41` 以降がグループを `chatTaskTodayExecutionGroups:日付` というlocalStorageへ別保存している。

この結果は通常JSONによる別保存領域への移行の制約。完全バックアップでグループが復元されるか、同一保存領域で本番／テストのグループが干渉するかは実画面で未検証のため、成功・失敗を断定しない。

#### CU-03：ブラウザー互換版でTask詳細にTauriのinvokeエラーが表示される

優先度：低（Web互換モードの制約）。Webで新規Taskを作成、またはTask詳細を選択すると、記録欄の下に `TypeError: Cannot read properties of undefined (reading 'invoke')` と表示される。Taskの表示・保存・今日・AI相談は継続できた。Desktopでは同じ表示はなく、添付追加・プレビューも成功した。

コード確認では `src/components/TaskDetail.tsx:122` がTask選択時に `listAttachments` を実行し、`src/services/attachments.ts:12` がTauriのinvokeを呼ぶ。Web非対応の添付処理に関するエラーと考えられる。Desktop固有機能の失敗として扱わない。

#### CU-04：対応順表示では、選択して持ち越すモードに入っても選択欄が出ない

優先度：低〜中。Webで確認。

1. 今日を「対応順」にする。
2. 「タスクを選んで2026-10-19へ回す」を押す。
3. 上部は「選択をやめる」「選択したタスクを…（0件）」になるが、作業行やグループに持ち越し用チェックボックスが表示されない。
4. 「ボード」に切り替えると各作業に「次の営業日に回す」が表示され、選択・持ち越しできる。

回避操作はボード表示への切替。グループを維持した対応順表示のまま対象を選べるか、選択モード開始時にボードへ切り替わると操作を完結できる。ボードからの持ち越し自体は成功した。

### 操作環境による制約・未確認事項

ファイル選択・出力時の以下のエラーは、アプリ側の不具合と操作ツール側の制約を切り分けられていない。ファイル選択画面が開いたことだけで合格としていない。

- WebのAI提案ファイル選択は、Chrome拡張の「ファイルのURLへのアクセスを許可する」が未許可で `setFiles` に失敗した。拡張の権限は変更していない。ファイル選択を自動操作する場合の設定案内は[公式ドキュメント](https://developers.openai.com/codex/app/chrome-extension#upload-files)を参照。
- WebのJSON書き出しはdownloadイベントの待機がタイムアウトしたが、実際のダウンロードファイルは存在し、架空データ4件を含むことを確認してDesktopの読み込みに使用した。
- Desktopのファイル選択では、AX上の選択後にOpenが無効のままになる場合や、`timeoutReached`／`noWindowsAvailable` が発生した。通常JSON読み込みと添付追加は完了したが、AI提案JSONのファイル読み込みは完了を確認できなかった。
- Desktopのまとめ出力クリック後もウィンドウ取得に失敗した。出力ファイルの存在・内容は未確認。終了操作後、最後のアプリ一覧では専用アプリが `isRunning: false` であることを確認した。
- これらの現象では、実際の画面変化とAXの更新にずれが生じる場合があった。スクリーンショットやDOMも確認し、確認できない結果を成功に含めていない。
