# 仕事用・個人ToDoツールへのプロジェクト管理機能導入案

## 改訂履歴

- 2026-07-26：同日の複数作業予定、マイルストーン順の表示、同日内の手動並び替え、連携ToDo候補、ガントチャートの期限着色範囲、画面移動時の最新データ再読込を追記

## 1. 本資料の目的

本資料は、仕事で個人利用するToDoツールに、日常用の個人管理システムで採用しているプロジェクト管理方法を導入するため、運用方法・画面構成・データ構造・内部仕様をまとめたものです。

本ツールは複数人で共同利用する会社システムではなく、利用者本人が自分の担当業務を管理するための個人用ツールです。

目的は、日々発生する小さなToDoから、複数工程を持つプロジェクトまでを、同じツール内で無理なく管理できるようにすることです。

## 2. 仕様を選択する際の方針

本仕様は、日常生活向けに作成している個人管理システムを基にしています。ただし、生活管理の仕様をそのまま仕事用ツールへ移植することを目的とはしません。

仕事用ToDoツールへ適用する際は、以下を考慮し、より仕事に適した方法がある場合は適宜そちらを採用します。

- 既存の案件タグとの整合性
- 仕事で使用している用語
- 期限・優先度・ステータスの扱い
- 業務報告や振り返りへの利用
- 日々の入力負担
- 業務ファイルの保存方法
- 検索性
- 操作の分かりやすさ
- 個人が継続して利用できる簡潔さ

複数ユーザー、担当者、承認、同時編集などの組織向け機能は基本的に対象外とします。

通常のToDo登録を最も簡単な状態に保ち、プロジェクト管理機能は必要になった場合だけ使用できる構成とします。

# 第1部　用語と管理単位

## 3. 案件タグ

既存の案件タグ機能と運用方法は変更しません。

案件タグはプロジェクトそのものではなく、ToDoやプロジェクトが所属する仕事上の分類として使用します。

案件タグの例は以下です。

- 顧客名
- 案件名
- 製品名
- システム名
- 保守業務
- 社内業務
- その他の仕事区分

一つの案件タグの中に、複数のプロジェクトと通常のToDoを登録できます。

```text
案件タグ：○○社システム更新
├─ プロジェクト：要件定義を完了する
├─ プロジェクト：データ移行を完了する
├─ ToDo：問い合わせに回答する
└─ ToDo：資料を送付する
```

この構成により、案件タグをプロジェクト化せず、同じ案件内にある大小のプロジェクトを個人単位で整理できます。

## 4. ToDo／ChatTask

仕事用ToDoツールにおける基本的な作業単位です。

元システムでは、チャット形式でメモや対応履歴を残せるため「ChatTask」と呼んでいます。仕事用ツールでは既存の名称に合わせて、TaskまたはToDoと表記できます。

本資料では、原則として「ToDo」と記載します。

ToDoには以下の情報を保持します。

- ToDo名
- 説明
- ステータス
- 優先度
- 期限
- 案件タグ
- 作業予定
- コメント
- 対応履歴
- 添付ファイル
- 関連するプロジェクト
- 関連するマイルストーン
- 関連する作業項目

依頼、問い合わせ、確認事項、単発作業などは、まずToDoとして登録します。

## 5. プロジェクト

元システムの「目標」機能を、仕事用ツールでは「プロジェクト」という名称に変更します。

プロジェクトは、複数の工程、中間到達点、作業予定などを管理する必要がある仕事に使用します。

プロジェクトには以下を持たせます。

- プロジェクト名
- 説明
- ステータス
- 案件タグ
- 起点ToDo
- GOAL
- GOAL期限
- マイルストーン
- 作業項目
- 進捗状況

## 6. GOAL

GOALの名称は変更しません。

GOALは、プロジェクトの最終的な達成条件を表します。

プロジェクト名が仕事のまとまりを表すのに対し、GOALは「どのような状態になればプロジェクトを完了と判断できるか」を表します。

```text
プロジェクト：固定資産税納付対応

GOAL：
期限内に納付を完了し、納付記録を保存する
```

GOALには期限を設定し、プロジェクト一覧と詳細画面に期限日および残り日数を表示します。

## 7. マイルストーン

マイルストーンは、GOALへ到達するまでの中間達成条件です。

原則として、具体的な作業ではなく「何が完了した状態か」を登録します。

```text
マイルストーン1：必要書類が揃っている
マイルストーン2：申請内容の確認が完了している
マイルストーン3：提出が完了している
GOAL：手続き全体が完了している
```

単純な内容の場合は、マイルストーンに作業項目を作成せず、マイルストーン自身のステータスだけで管理できます。

## 8. 作業項目

マイルストーンやGOALを達成するための具体的な行動です。

元システムではTaskと呼んでいますが、通常のToDoとの区別が分かりにくい場合は、仕事用ツールでは「作業項目」などの名称を使用します。

作業項目の作成は任意です。

```text
マイルストーン：必要書類が揃っている
├─ 作業項目：申請書を取得する
├─ 作業項目：前年度資料を確認する
└─ 作業項目：添付資料を準備する
```

作業を分解する必要がなければ、作業項目を作成せずマイルストーンだけで管理します。

## 9. 作業予定

ToDoには、期限とは別に複数の作業予定を設定できます。

- 期限：完了しなければならない日
- 作業予定：実際に作業する日または期間

各作業予定には以下を設定します。

- 開始日
- 終了日
- 作業内容
- ステータス
- 関連するマイルストーンまたは作業項目

同じToDoに対して、開始日が同じ作業予定を複数登録できるものとします。同じ日に複数の作業を行う場合でも、一つのメモへまとめることを強制しません。

ToDoの簡易作成画面では、作業予定を設定しません。簡易作成ではToDo名・優先度・期限だけを入力し、実際に作業する日や期間は、作成後の詳細画面から必要な場合だけ追加します。

# 第2部　基本的な運用方法

## 10. ToDoから始める運用

すべての仕事を最初からプロジェクトとして登録する必要はありません。

まず通常のToDoとして登録し、対応を進める中で作業規模が大きくなった場合だけプロジェクトへ昇華します。

```text
依頼・気付き
↓
通常のToDoとして登録
↓
単純な作業はそのまま対応・完了
↓
複数工程の管理が必要になる
↓
プロジェクトへ昇華
↓
マイルストーン・作業項目・作業予定を設定
↓
GOAL達成まで管理
```

## 11. ToDoのまま管理する仕事

以下のような仕事は、プロジェクト化せず通常のToDoとして管理します。

- 一度の対応で完了する
- 中間到達点が不要
- 手順が単純である
- 個別の進捗管理が不要
- コメントと期限だけで管理できる
- 短期間で完了する

## 12. プロジェクトへの昇華を検討する仕事

以下に該当する場合は、プロジェクトへの昇華を検討します。

- 複数日にわたる
- 複数の工程がある
- 中間到達点を管理したい
- 関連するToDoやファイルが増えている
- 複数の作業予定がある
- 最終的な完了条件を明確にしたい
- 通常のToDoだけでは全体像を把握しにくい

## 13. ToDoからプロジェクトへの昇華

ToDoの三点リーダーメニューに「プロジェクトへ昇華」を追加します。

選択すると、対象ToDoの情報を初期値としてプロジェクト作成画面を表示します。

引き継ぐ情報は以下です。

- ToDo名 → プロジェクト名
- ToDoの説明 → プロジェクトの説明
- ToDoの期限 → GOAL期限
- 案件タグ → プロジェクトの案件タグ
- 元のToDo → 起点ToDo

利用者は、作成前にプロジェクト名、説明、GOAL、期限などを変更できます。

## 14. 元のToDoの扱い

プロジェクトへ昇華しても、元のToDoは削除・移動・複製しません。

元のToDoは「起点ToDo」としてプロジェクトへ関連付けます。

元のToDoには以下を残します。

- これまでのコメント
- 対応経緯
- 作業メモ
- 添付ファイル
- 作業予定
- ステータス変更履歴

プロジェクト画面には「起点ToDo・これまでの経緯」を表示し、クリックすると元のToDoへ移動できるようにします。

```text
プロジェクト
├─ 起点ToDo
│  ├─ コメント
│  ├─ 対応履歴
│  ├─ 作業予定
│  └─ 添付ファイル
├─ マイルストーン
├─ 作業項目
└─ GOAL
```

## 15. プロジェクトからToDoへ戻す操作

専用の「ToDoへ戻す」機能は設けません。

昇華はToDoをプロジェクトへ変換する処理ではなく、元のToDoを残したままプロジェクトを追加する処理です。

プロジェクト管理が不要になった場合は、プロジェクトだけを削除します。プロジェクトを削除しても、起点ToDoとその記録は残します。

# 第3部　プロジェクト画面

## 16. プロジェクト一覧

プロジェクト一覧には以下を表示します。

- プロジェクト名
- 案件タグ
- ステータス
- GOAL期限
- 残り日数
- 進捗率
- 完了した作業項目数
- 全作業項目数

プロジェクトのステータスは以下を基本とします。

- 未着手
- 進行中
- 一時停止
- 達成
- アーカイブ

仕事用ToDoツールに既存のステータスがある場合は、既存の定義を優先できます。

## 17. 表示ステータス

一覧に表示するステータスを選択できるようにします。

例：

- 未着手だけ表示
- 未着手と進行中を表示
- 達成済みを含めて表示
- アーカイブを非表示

表示設定はローカルに保存し、アプリを再起動しても維持します。

## 18. 並び替え

複数の並び替え条件を、優先順に設定できるようにします。

```text
優先度：降順
　　↓
残り日数：昇順
　　↓
更新日時：降順
```

並び替え条件の候補は以下です。

- 優先度
- GOAL期限
- 残り日数
- 進捗率
- 作成日時
- 更新日時
- プロジェクト名

並び替え設定も再起動後に維持します。

## 19. プロジェクト詳細

詳細画面上部には以下を表示します。

- プロジェクト名
- 説明
- 案件タグ
- ステータス
- GOAL
- GOAL期限
- 残り日数
- 進捗率
- ボード／ツリー表示切り替え
- 三点リーダー

三点リーダーには以下を格納します。

- プロジェクトを編集
- 起点ToDoを表示
- 詳細表示
- プロジェクトを削除

頻繁に使用するステータス変更は、三点リーダーに隠さず画面上で直接操作できるようにします。

## 20. 起点ToDoの表示

ToDoから昇華したプロジェクトには「起点ToDo・これまでの経緯」を表示します。

表示内容は以下です。

- ToDo名
- 説明の一部
- 案件タグ
- 現在のステータス
- 「ToDoを開く」操作

コメントや添付ファイルはプロジェクトへコピーせず、元のToDoを参照します。

# 第4部　ボード・ツリー表示

## 21. ボード表示

ボード表示では、マイルストーンと作業項目を一覧形式で確認します。

主な操作は以下です。

- マイルストーンの作成
- マイルストーンの編集・削除
- 作業項目の作成
- 作業項目の編集・削除
- ステータスの直接変更
- 期限の確認
- 説明の確認
- 連携ToDoの確認
- 完了項目の表示・非表示

編集・削除は三点リーダーに格納します。

## 22. ツリー表示

ツリー表示では、プロジェクトがGOALへ進む流れを視覚的に表します。

```text
開始
↓
マイルストーン1
↓
マイルストーン2
↓
マイルストーン3
↓
GOAL
```

表示仕様は以下です。

- マイルストーンは期限が近い順に上から表示
- GOALは最下部に配置
- GOALより下には枝を作成しない
- 作業項目は所属するマイルストーンの下へ表示
- 左右交互配置または片側配置を選択可能
- 表示方式はローカルに保存
- マイルストーンごとに作業項目を開閉可能
- 開閉状態はプロジェクト単位で保持
- 幹の途中からマイルストーンを追加可能
- 作業項目の下から次の作業項目を追加可能

## 23. 達成状態の表示

達成済みのマイルストーンは、以下を緑色で表示します。

- マイルストーンカード
- マイルストーンへ伸びる枝
- 次のマイルストーン直前までの幹

複数の作業項目をマイルストーンの達成条件とする場合は、すべて完了した時点で表示色を変更します。

マイルストーンを自動的に完了へ変更するか、利用者が明示的に完了へ変更するかは、仕事での使いやすさを確認して選択します。

# 第5部　ToDoとの連携

## 24. 連携ルール

マイルストーンおよび作業項目には、既存のToDoを任意で連携できます。

- 一つのマイルストーンが連携できるToDoは最大1件
- 一つの作業項目が連携できるToDoは最大1件
- 一つのToDoは複数のマイルストーンや作業項目から参照可能
- GOALにはToDoを直接連携しない
- ToDoとの連携は必須にしない

作業記録が不要な単純な項目は、ToDoを作成せずプロジェクト画面上だけで管理できます。

## 25. ToDo検索・新規作成

ToDoの件数が増えることを想定し、候補をすべて画面上へ並べる方式にはしません。

「ToDoを検索・作成」ボタンから選択画面を開きます。

検索画面では以下を提供します。

- ToDo名による検索
- 案件タグによる絞り込み
- ステータスによる絞り込み
- 最近使用したToDo
- 同じ案件タグのToDo
- 同じマイルストーンで使用しているToDo
- プロジェクトの起点ToDo
- プロジェクト直属の作業項目に連携されているToDo
- 新規ToDoの作成

新規ToDoは、検索を実行しなくても作成できるようにします。

マイルストーンから連携ToDoを設定する場合は、検索画面を開く前に、同じプロジェクト内の候補を優先表示します。候補は、起点ToDoおよびプロジェクト直属の作業項目に連携されているToDoから作成します。

候補は選択を補助するためのものであり、候補外のToDoを検索して選択する操作も残します。候補を画面上へ無制限に列挙せず、該当する少数の候補だけを表示します。

## 26. 連携先への移動

マイルストーンまたは作業項目にToDoが連携されている場合は、連携先ToDoへ移動できるようにします。

ToDo画面には、そのToDoが連携されている以下の一覧を表示します。

- プロジェクト
- マイルストーン
- 作業項目

一覧からプロジェクト画面へ移動でき、マイルストーンや作業項目のステータスも変更できるようにします。

連携一覧は詳細表示と同じように折りたたみ可能とし、通常時は三点リーダー内に格納します。

# 第6部　スケジュール

## 27. 作業予定の登録

ToDoには複数の作業予定を設定できます。

各作業予定には以下を登録します。

- 開始日
- 終了日
- その期間に行うこと
- 作業単位のステータス
- 関連するマイルストーンまたは作業項目

作業内容は改行可能とします。

作業単位のステータスは以下です。

- 未着手
- 進行中
- 完了

同一ToDo内で開始日が重複しても登録を許可します。開始日だけを一意条件にせず、作業内容や関連するマイルストーンが異なる予定を個別の作業単位として保持します。

作業予定の表示順は、作成順ではなく以下を基本とします。

1. 関連するマイルストーンの順序
2. 作業予定の開始日
3. 同一マイルストーン・同一開始日内の手動順序
4. 作成日時

同じマイルストーン内で同じ開始日の作業予定が複数ある場合は、上へ／下へ操作で順番を変更できるようにします。手動順序はデータベースへ保存し、再起動後も維持します。

## 28. プロジェクトからの予定編集

マイルストーンや作業項目にToDoが連携されている場合は、プロジェクト画面からそのToDoの予定を登録・編集できます。

この場合、どの予定がどのマイルストーンまたは作業項目に関連しているかをデータとして保持します。

プロジェクト画面には、現在編集中のマイルストーンまたは作業項目に関連する予定だけを表示します。

関係のない予定は表示・編集対象に含めません。

## 29. 今日の画面

今日の画面には、選択した日付の作業予定を表示します。

表示対象は以下です。

- その日に予定されているToDo
- プロジェクトに関連する作業予定
- 期限が到来するToDo
- 必要な場合は定期作業

完了済み項目の表示・非表示を切り替えられるようにし、設定を再起動後も保持します。

## 30. ガントチャート

ガントチャートは、ToDoの期限ではなく登録された作業予定を基に線を表示します。

- 開始日から終了日までToDoごとに線を表示
- 複数日にまたがる予定に対応
- 一つのToDoに複数の予定を表示可能
- 期限日には旗を表示
- 登録していない日付を予定として表示しない
- 完了した項目は初期状態で非表示
- 表示・非表示を項目単位で切り替え可能
- 作業内容をガントチャート上で編集可能
- 三点リーダーからToDoやプロジェクトへ移動可能

表示順はToDoや作業予定の作成順ではなく、関連するプロジェクトのマイルストーン順を優先します。同一マイルストーンかつ同一開始日の作業は、保存された手動順序に従います。

期限日の背景色は、期限の階層に応じて着色範囲を分けます。

- GOAL期限：日付ヘッダーから表の最下部まで、該当日の列全体を着色
- マイルストーン期限：そのマイルストーンに紐づく作業予定の行だけを着色
- ToDo期限：該当ToDoの見出し行だけを着色し、期限旗も表示

これにより、プロジェクト全体の最終期限と、特定のマイルストーン・ToDoだけに関係する期限を区別します。

ガントチャートを開いたときは、作業予定だけでなく、プロジェクト、マイルストーン、作業項目、関連情報をSQLiteから再取得します。別画面で期限や関連先を変更した場合も、ガントチャートへ移動した時点で最新状態を反映します。

# 第7部　ファイル管理

## 31. ファイルの保存元

ファイル本体はToDoに保存し、プロジェクト側へ複製しません。

プロジェクト、マイルストーン、作業項目には、ファイルを利用する目的を表す関連情報だけを保存します。

```text
ToDo
└─ 添付ファイル
   ├─ 関連プロジェクト
   ├─ 関連マイルストーン
   └─ 関連作業項目
```

この構成により、同じファイルを複数の作業で使用しても重複保存を防げます。

## 32. ファイルの関連先

ファイルの関連先は任意とします。

- ToDo画面から添付：初期値は「ToDo全体」
- 作業項目から添付：その作業項目を自動設定
- マイルストーンから添付：そのマイルストーンを自動設定
- 複数の作業で利用：複数関連を許可
- 後から三点リーダーで関連先を変更可能

ファイル名の下には、関連先をパンくず形式で表示します。

```text
見積書.pdf
○○社システム更新 ＞ 要件定義 ＞ 見積内容を確認
```

関連先が設定されていない場合は「ToDo全体」と表示します。

## 33. ファイルの削除

- コメントを削除してもファイル本体は削除しない
- ファイル本体は専用の削除操作でのみ削除
- マイルストーンや作業項目を削除してもファイル本体は残す
- 関連先が削除された場合は「ToDo全体」のファイルとして保持
- ファイル名変更時に拡張子は変更対象にしない

仕事用ツールの保存方式に適した方法がある場合は、以下から選択します。

- ツール管理フォルダへコピー
- 会社指定フォルダへの参照
- ファイルパスだけを記録
- 文書管理システムのURLを記録

ファイルの扱いは、会社の情報管理規則に合う方法を優先します。

# 第8部　進捗と優先度

## 34. 進捗率

作業項目が存在する場合は、作業項目の完了数を基本として計算します。

```text
完了した作業項目数 ÷ 全作業項目数 × 100
```

作業項目を持たないマイルストーンは、マイルストーン自身の完了状態を計算対象に含めます。

ただし、単純な件数による進捗率が実際の仕事量と合わない可能性があります。その場合は以下から適切な方法を選択します。

- 作業項目数による自動計算
- マイルストーン数による自動計算
- 重み付けによる計算
- 手動入力
- 進捗率を表示せずステータスだけを使用

仕事上の判断を誤らせる場合は、無理に進捗率を表示しません。

## 35. 優先度

優先度はA・B・C・Dへ統一します。

- A：赤系・最優先
- B：青系
- C：緑系
- D：紫系・低優先

並び替えではAからDの順を降順として扱います。

仕事用ToDoツールに既存の優先度定義がある場合は、既存定義との対応表を設けます。

# 第9部　内部仕様

## 36. Project

```text
Project
- id
- title
- description
- status
- case_tag_id
- goal_text
- goal_due_date
- origin_todo_id
- created_at
- updated_at
```

`origin_todo_id`は任意です。ToDoから昇華したプロジェクトの場合だけ設定します。

## 37. Milestone

```text
Milestone
- id
- project_id
- title
- description
- status
- target_date
- sort_order
- linked_todo_id
- created_at
- updated_at
```

## 38. ProjectWorkItem

```text
ProjectWorkItem
- id
- project_id
- milestone_id
- title
- description
- status
- priority
- due_date
- linked_todo_id
- created_at
- updated_at
```

`milestone_id`は任意とし、マイルストーンに所属しない作業項目も許可します。

## 39. TaskSchedule

```text
TaskSchedule
- id
- todo_id
- milestone_id
- work_item_id
- start_date
- end_date
- status
- work_note
- sort_order
- created_at
- updated_at
```

`milestone_id`と`work_item_id`は任意です。どちらも設定されていない予定はToDo全体の作業予定として扱います。

`sort_order`は、同一マイルストーン・同一開始日内における利用者指定の表示順を保持します。

`todo_id`と`start_date`の組み合わせには一意制約を設けません。同じToDo・同じ開始日に複数の作業予定を登録できる構造とします。

プロジェクトは、`milestone_id`または`work_item_id`から特定できるため、原則としてTaskScheduleへ`project_id`を重複保存しません。既存システムとの統合上必要な場合だけ保持を検討します。

実際の実装では、既存データ構造と重複する項目を整理し、中間テーブルなど適切な方式を採用します。

## 40. FileRelation

```text
FileRelation
- file_id
- project_id
- milestone_id
- work_item_id
- created_at
```

一つのファイルを複数の作業項目へ関連付ける場合は、中間テーブル方式を使用します。

## 41. 昇華処理

ToDoからプロジェクトへの昇華処理は以下です。

1. 対象ToDoを取得
2. 既に起点プロジェクトが存在するか確認
3. ToDoの情報をプロジェクト作成画面へ初期表示
4. 利用者が内容を確認・編集
5. Projectを新規作成
6. `origin_todo_id`へ対象ToDoのIDを保存
7. 案件タグを引き継ぐ
8. 作成したプロジェクトを表示

元のToDo、コメント、ファイル、作業予定は更新・削除しません。

昇華済みのToDoでは、三点リーダーの表示を以下のように変更します。

- 昇華前：「プロジェクトへ昇華」
- 昇華後：「起点プロジェクトを開く」

## 42. データ関係

起点ToDoとの関係は、以下のように扱います。

```sql
origin_todo_id REFERENCES todos(id) ON DELETE SET NULL
```

これにより、起点ToDoが削除されてもプロジェクトは残り、起点参照だけが解除されます。

原則として、一つのToDoから作成する起点プロジェクトは一つとします。

ただし、仕事上、一つのToDoから複数プロジェクトが派生する運用が必要になった場合は、中間テーブル方式へ変更できる構成とします。

## 43. 削除仕様

- プロジェクト削除時に起点ToDoを削除しない
- 起点ToDo削除時にプロジェクトを削除しない
- 起点ToDo削除時は起点参照だけを解除
- プロジェクト削除時は配下のマイルストーンと作業項目を削除対象とする
- 連携ToDoは削除しない
- コメント削除時にファイル本体を削除しない
- ファイル本体は専用操作でのみ削除
- 削除前に対象範囲を表示して確認する
- 必要に応じて削除前の自動バックアップを作成する

# 第10部　保存・バックアップ

## 44. 保存方式

仕事用ツールも個人利用を前提とするため、主要データは端末内へ保存します。

- ToDo、プロジェクト、マイルストーンなど：SQLite
- 添付ファイル：ローカルの管理フォルダ
- ファイル情報と関連先：SQLite
- 一時的な表示状態：LocalStorageまたは設定テーブル
- 重要な表示設定：可能であればSQLiteの設定テーブル

主要データをLocalStorageだけに保存しません。

## 45. バックアップ

以下をバックアップ対象とします。

- SQLiteデータベース
- アプリ内保存ファイル
- 設定情報

最低限、以下の機能を用意します。

- バックアップファイルの作成
- 保存先の選択
- バックアップからの復元
- 復元前の確認
- 復元前の自動バックアップ
- JSONまたはZIPによるエクスポート
- データのインポート

仕事上のファイルを扱うため、保存先とバックアップ先は会社の情報管理規則に従います。

## 46. 初期実装

最初に必要な機能は以下です。

基本運用を確認した後、必要に応じて以下を追加します。

- ツリー表示

# 49. 期待される効果

この仕組みにより、仕事を登録する時点で、その作業がToDoなのかプロジェクトなのかを正確に判断する必要がなくなります。

最初は通常のToDoとして開始し、必要になったものだけをプロジェクトへ発展させられます。

また、案件タグの現在の運用を変更せず、同じ案件内に存在する大小の仕事を個人単位で整理できます。

主な効果は以下です。

- ToDoの再登録を防止できる
- 過去のコメントや添付ファイルを失わない
- 小さな依頼と大きな仕事を同じ入口から管理できる
- GOALと中間到達点を明確にできる
- 期限と実際の作業日を分けて管理できる
- 案件ごとの対応経緯を追跡しやすくなる
- 今日行う仕事を明確にできる
- 完了後の振り返りや作業報告に利用できる

本機能は、個人用ToDoツールを複雑な組織向けプロジェクト管理システムへ変更するものではありません。

通常のToDo管理を簡潔な状態に保ちながら、必要な仕事だけを段階的にプロジェクト管理へ発展させることを目的とします。
